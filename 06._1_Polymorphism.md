# Java OOP — Polymorphism

## 1. What is Polymorphism?

**Polymorphism** means:

> **One name, multiple forms.**

In Java, the same method name or operation can behave differently depending on the situation.

Example:

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

Here, `add()` has multiple forms.

```text
add(10, 20)
     ↓
2 parameters

add(10, 20, 30)
     ↓
3 parameters
```

Same method name → different forms → **Polymorphism**

---

# 2. Types of Polymorphism in Java

There are two important types:

```text
Polymorphism
     │
     ├── Compile-time Polymorphism
     │       └── Method Overloading
     │
     └── Runtime Polymorphism
             └── Method Overriding
```

---

# 3. Compile-Time Polymorphism

Compile-time polymorphism is mainly achieved through **method overloading**.

The compiler determines which method should be called based on the method arguments.

### Example

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}
```

Calling:

```java
Calculator c = new Calculator();

System.out.println(c.add(10, 20));
System.out.println(c.add(10, 20, 30));
System.out.println(c.add(10.5, 20.5));
```

The compiler identifies the correct method based on the arguments.

---

# 4. Method Overloading

**Method overloading** means having multiple methods with the **same method name but different parameter lists** within the same class.

Example:

```java
class Login {

    void login() {
        System.out.println("Login without credentials");
    }

    void login(String username) {
        System.out.println("Login with username");
    }

    void login(String username, String password) {
        System.out.println("Login with username and password");
    }
}
```

All methods have the same name:

```text
login()
login(String)
login(String, String)
```

But their parameter lists are different.

---

# 5. What Can Be Different in Method Overloading?

The parameter list can differ by:

### Number of parameters

```java
void test(int a) {
}

void test(int a, int b) {
}
```

### Data type of parameters

```java
void test(int a) {
}

void test(String a) {
}
```

### Order of parameter types

```java
void test(int a, String b) {
}

void test(String a, int b) {
}
```

---

# 6. What Is NOT Method Overloading?

Changing **only the return type** is not enough.

Incorrect:

```java
int add(int a, int b) {
    return a + b;
}

double add(int a, int b) {
    return a + b;
}
```

This gives a compilation error because the parameter list is identical.

Remember:

> **Return type alone cannot differentiate overloaded methods.**

---

# 7. Constructor Overloading

Constructor overloading is also commonly considered a form of **compile-time polymorphism**.

Example:

```java
class Login {

    Login() {
        System.out.println("No credentials");
    }

    Login(String username) {
        System.out.println(username);
    }

    Login(String username, String password) {
        System.out.println(username + " " + password);
    }
}
```

Different ways to create objects:

```java
Login user1 = new Login();

Login user2 = new Login("Ramesh");

Login user3 = new Login("Ramesh", "Password@123");
```

Same constructor name, different parameter lists.

---

# 8. Runtime Polymorphism

Runtime polymorphism is achieved through **method overriding**.

It occurs when a child class provides its own implementation of a method that already exists in the parent class.

Example:

```java
class Browser {

    void open() {
        System.out.println("Opening browser");
    }
}

class Chrome extends Browser {

    @Override
    void open() {
        System.out.println("Opening Chrome");
    }
}

class Firefox extends Browser {

    @Override
    void open() {
        System.out.println("Opening Firefox");
    }
}
```

Now:

```java
Browser browser;

browser = new Chrome();
browser.open();
```

Output:

```text
Opening Chrome
```

Then:

```java
browser = new Firefox();
browser.open();
```

Output:

```text
Opening Firefox
```

The reference type is:

```java
Browser
```

But the actual object is:

```java
Chrome
```

or:

```java
Firefox
```

The method that executes is determined at **runtime**.

---

# 9. Why Is It Called Runtime Polymorphism?

Look at this:

```java
Browser browser = new Chrome();

browser.open();
```

The compiler knows:

```text
browser → Browser reference
```

But at runtime, the actual object is:

```text
Chrome object
```

Therefore the overridden `Chrome.open()` executes.

```text
Browser reference
       ↓
Chrome object
       ↓
Chrome.open()
```

This is runtime polymorphism.

---

# 10. Method Overloading vs Method Overriding

| Feature               | Overloading                                     | Overriding                    |
| --------------------- | ----------------------------------------------- | ----------------------------- |
| Polymorphism          | Compile-time                                    | Runtime                       |
| Classes               | Usually same class                              | Parent + child                |
| Method name           | Same                                            | Same                          |
| Parameters            | Must be different                               | Normally same                 |
| Return type           | Can differ subject to Java rules, but not alone | Same or compatible/covariant  |
| Inheritance required? | No                                              | Yes                           |
| Decision              | Compile time                                    | Runtime                       |
| Main concept          | Multiple forms of a method                      | Child changes parent behavior |

---

# 11. Simple Way to Remember

### Overloading

Think:

> **Same class → same method name → different inputs**

```text
login()
login(username)
login(username, password)
```

### Overriding

Think:

> **Parent + Child → same method → child provides different behavior**

```text
Browser
   ↓
Chrome
   ↓
open() → Chrome behavior
```

# 12. Polymorphism and Inheritance

Inheritance and runtime polymorphism are closely related.

Example:

```java
class Browser {

    void open() {
        System.out.println("Browser");
    }
}

class Chrome extends Browser {

    @Override
    void open() {
        System.out.println("Chrome");
    }
}
```

`Chrome` inherits from `Browser`.

```java
Chrome c = new Chrome();
```

And:

```java
Browser b = new Chrome();
```

allows runtime polymorphism.

So:

```text
Inheritance
    +
Method Overriding
    ↓
Runtime Polymorphism
```

# 13. Real Automation Example

Consider browser automation.

You may have:

```java
class Browser {

    void launch() {
        System.out.println("Launching browser");
    }
}
```

Chrome:

```java
class Chrome extends Browser {

    @Override
    void launch() {
        System.out.println("Launching Chrome");
    }
}
```

Firefox:

```java
class Firefox extends Browser {

    @Override
    void launch() {
        System.out.println("Launching Firefox");
    }
}
```

Now:

```java
Browser browser;

browser = new Chrome();
browser.launch();

browser = new Firefox();
browser.launch();
```

The same call:

```java
browser.launch();
```

produces different behavior depending on the actual object.

This is the practical idea behind polymorphism in automation frameworks.

# 14. Polymorphism + Reference + Object

This is very important.

```java
Browser browser = new Chrome();
```

There are two sides:

```text
Browser browser
      ↑
Reference type

new Chrome()
      ↑
Actual object type
```

The reference type determines what members are accessible through the reference.

The actual object determines which overridden implementation executes at runtime.

# 15. Important Interview Points

### Q: What is polymorphism?

> Polymorphism is an OOP concept where one name can have multiple forms or behaviors.

### Q: Types of polymorphism?

> Compile-time polymorphism and runtime polymorphism.

### Q: How is compile-time polymorphism achieved?

> Mainly through method overloading.

### Q: How is runtime polymorphism achieved?

> Through method overriding.

### Q: Is inheritance required for method overloading?

> No.

### Q: Is inheritance required for method overriding?

> Yes.

### Q: Can we overload a method by changing only its return type?

> No.

### Q: Can constructors be overloaded?

> Yes.

### Q: Can constructors be overridden?

> No. Constructors are not inherited, so they cannot be overridden.

```text
                    POLYMORPHISM
                         │
              ┌──────────┴──────────┐
              │                     │
        Compile Time            Runtime
              │                     │
        Method Overloading     Method Overriding
              │                     │
       Same name               Parent + Child
       Different parameters    Same method signature
              │                     │
       Compiler decides        JVM decides at runtime
```
